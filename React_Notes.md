To see the updated count, the entire web page had to be reloaded/re-rendered.Poor User Experience: Constantly reloading static HTML pages for small data changes created a sluggish and clunky experience for millions of daily active users.How React Solved It (The Solution \& Birth of React):To tackle this DOM updating issue, Jordan Walke (a software engineer at Facebook) created React to overhaul how dynamic user interfaces are built:Component-Based Architecture : Instead of treating a web page as a single massive HTML document, React breaks the UI down into independent, reusable chunks (components). If a notification count changes, only that specific notification component re-renders while the rest of the page remains untouched.Virtual DOM : React introduced a Virtual DOM (an in-memory lightweight copy of the real DOM). Whenever state changes occur, React compares the Virtual DOM with the Real DOM and updates only the specific elements that actually changed, making applications buttery smooth and fast without full-page reloads.Official Release : Facebook initially deployed React on News Feed (2011) and later Instagram (2012), before open-sourcing it to the public in 2013.different types of js library(library are used to add features in a website):&#x20; React\----------------------------------------\- React is a JavaScript library for building user interfaces (UI).\- It is mainly focused on the UI/view layer.\- React is flexible, so we can choose additional tools/libraries&#x20; according to our project needs.React vs Angular/Vue:\- React -> Library, more flexible\- Angular -> Framework, more opinionated/full solution\- Vue -> Framework, provides more built-in structure/features========================================2\. JSX========================================JSX = JavaScript XML\- JSX allows us to write HTML-like syntax inside JavaScript.\- It makes React UI code easier to write and understand.\- JSX is NOT exactly HTML; it is syntax that gets transformed&#x20; into JavaScript.Example:const name = "Ayush";const App = () => {&#x20;   return <h1>Hello {name}</h1>;};========================================3\. JSX RULES========================================1\. Only one parent element can be returned.Correct:<div>&#x20;   <h1>Hello</h1>&#x20;   <p>Welcome</p></div>OR use Fragment:<>&#x20;   <h1>Hello</h1>&#x20;   <p>Welcome</p></>2\. Use className instead of class.HTML:<div class="card">JSX:<div className="card">3\. All tags must be properly closed.Correct:<img /><input /><br />4\. JavaScript expressions are written inside { }.Example:const name = "Ayush";<h1>Hello {name}</h1>5\. Inline CSS uses a JavaScript object and camelCase properties.Example:<h1 style={{ fontSize: "30px", backgroundColor: "red" }}>&#x20;   Hello</h1>CSS:font-sizebackground-colorJSX:fontSizebackgroundColor========================================4\. JSX EXPRESSIONS========================================Curly braces { } allow JavaScript expressions inside JSX.Example:const name = "Ayush";const age = 22;return (&#x20;   <div>&#x20;       <h1>{name}</h1>&#x20;       <p>{age}</p>&#x20;       <p>{2 + 2}</p>&#x20;   </div>);Output:Ayush224========================================5\. VITE========================================Vite is a modern frontend development/build tool.It is commonly used to create and run React projects.Creating a React project:**npm create vite@latest**Then:npm installRun development server:npm run devVite provides:\- Fast development server\- Fast updates during development\- Production build========================================6\. IMPORTANT VITE FILES========================================package.json\- Contains project information.\- Contains dependencies.\- Contains npm scripts.Example:"scripts": {&#x20;   "dev": "vite"}package-lock.json\- Records the exact dependency versions installed.\- Usually should NOT be manually edited.index.html\- Main HTML entry point of the Vite application.\- Contains the root element where React is mounted.vite.config.js\- Configuration file for Vite.\- Used to customize Vite behavior/plugins/settings.eslint.config.js\- Configuration file for ESLint.\- Defines rules/settings used to check JavaScript/React code.README.md\- Documentation/instructions about the project..gitignore\- Specifies files/folders that Git should not track.\- Example: node\_modules/, .env========================================7\. ESLINT========================================ESLint = JavaScript/React code analysis tool.Uses:\- Finds potential errors.\- Detects problematic code.\- Finds unused variables.\- Enforces coding standards.\- Helps maintain consistent code in team projects.eslint.config.js= tells ESLint which rules/settings to use.Interview:"ESLint is a static code-analysis tool used to identifypotential errors and enforce coding standards in JavaScriptand React projects."========================================8\. REACT COMPONENTS========================================Component:\- A reusable and independent building block of a React UI.\- Usually a JavaScript function that returns JSX.Example:const Card = () => {&#x20;   return (&#x20;       <div>&#x20;           <h1>My Card</h1>&#x20;       </div>&#x20;   );};========================================9\. FUNCTIONAL COMPONENT========================================A functional component is a JavaScript function that returns JSX.Example:const Navbar = () => {&#x20;   return <nav>This is Navbar</nav>;};========================================10\. COMPONENT REUSABILITY========================================The same component can be used multiple times.Example:<Card /><Card /><Card />This avoids writing the same UI code repeatedly.Benefits:\- Reusability\- Better organization\- Easier maintenance\- Breaks large UI into smaller parts========================================11\. COMPONENT COMPOSITION========================================Large UIs can be created by combining smaller components.Example:App&#x20;|&#x20;+-- Navbar&#x20;+-- Card&#x20;+-- Card&#x20;+-- Card&#x20;+-- FooterExample:const App = () => {&#x20;   return (&#x20;       <>&#x20;           <Navbar />&#x20;           <Card />&#x20;           <Card />&#x20;           <Card />&#x20;           <Footer />&#x20;       </>&#x20;   );};========================================12\. COMPONENT NAMING========================================React component names should start with a CAPITAL letter.Correct:<Card /><Navbar /><Footer />Incorrect:<card /><navbar /><footer />Why?JSX uses capitalization to distinguish React componentsfrom built-in HTML elements.Lowercase:<div /><button /><p />\-> treated as HTML elements.Capitalized:<Card /><Navbar />\-> treated as React components.Interview:"React component names must start with an uppercase letterbecause JSX uses capitalization to distinguish user-definedReact components from built-in HTML elements."========================================13\. IMPORT \& EXPORT========================================Export:export default Card;Import:import Card from "./Components/Card";Then use:<Card />Flow:Card.jsx&#x20;  ↓export&#x20;  ↓App.jsx&#x20;  ↓import&#x20;  ↓<Card />========================================14\. VARIABLES INSIDE COMPONENTS========================================Example:const Card = () => {&#x20;   const name = "Ayush";&#x20;   return (&#x20;       <h1>My name is {name}</h1>&#x20;   );};\- name is local to the Card component.\- It can be used inside Card.\- {name} inserts the JavaScript value into JSX.JavaScript uses lexical scoping, so a function can alsoaccess variables from its surrounding scope.========================================15\. IMPORTANT: PROPS========================================Props are conceptually similar to passing parametersto a function.Example idea:<Card name="Ayush" />The Card component can receive the name.More details will be covered separately.========================================
