To see the updated count, the entire web page had to be reloaded/re-rendered.Poor User Experience: Constantly reloading static HTML pages for small data changes created a sluggish and clunky experience for millions of daily active users.How React Solved It (The Solution & Birth of React):To tackle this DOM updating issue, Jordan Walke (a software engineer at Facebook) created React to overhaul how dynamic user interfaces are built:Component-Based Architecture : Instead of treating a web page as a single massive HTML document, React breaks the UI down into independent, reusable chunks (components). If a notification count changes, only that specific notification component re-renders while the rest of the page remains untouched.Virtual DOM : React introduced a Virtual DOM (an in-memory lightweight copy of the real DOM). Whenever state changes occur, React compares the Virtual DOM with the Real DOM and updates only the specific elements that actually changed, making applications buttery smooth and fast without full-page reloads.Official Release : Facebook initially deployed React on News Feed (2011) and later Instagram (2012), before open-sourcing it to the public in 2013.different types of js library(library are used to add features in a website):  - React----------------------------------------- React is a JavaScript library for building user interfaces (UI).- It is mainly focused on the UI/view layer.- React is flexible, so we can choose additional tools/libraries  according to our project needs.React vs Angular/Vue:- React -> Library, more flexible- Angular -> Framework, more opinionated/full solution- Vue -> Framework, provides more built-in structure/features========================================2. JSX========================================JSX = JavaScript XML- JSX allows us to write HTML-like syntax inside JavaScript.- It makes React UI code easier to write and understand.- JSX is NOT exactly HTML; it is syntax that gets transformed  into JavaScript.Example:const name = "Ayush";const App = () => {    return <h1>Hello {name}</h1>;};========================================3. JSX RULES========================================1. Only one parent element can be returned.Correct:<div>    <h1>Hello</h1>    <p>Welcome</p></div>OR use Fragment:<>    <h1>Hello</h1>    <p>Welcome</p></>2. Use className instead of class.HTML:<div class="card">JSX:<div className="card">3. All tags must be properly closed.Correct:<img /><input /><br />4. JavaScript expressions are written inside { }.Example:const name = "Ayush";<h1>Hello {name}</h1>5. Inline CSS uses a JavaScript object and camelCase properties.Example:<h1 style={{ fontSize: "30px", backgroundColor: "red" }}>    Hello</h1>CSS:font-sizebackground-colorJSX:fontSizebackgroundColor========================================4. JSX EXPRESSIONS========================================Curly braces { } allow JavaScript expressions inside JSX.Example:const name = "Ayush";const age = 22;return (    <div>        <h1>{name}</h1>        <p>{age}</p>        <p>{2 + 2}</p>    </div>);Output:Ayush224========================================5. VITE========================================Vite is a modern frontend development/build tool.It is commonly used to create and run React projects.Creating a React project:npm create vite@latestThen:npm installRun development server:npm run devVite provides:- Fast development server- Fast updates during development- Production build========================================6. IMPORTANT VITE FILES========================================package.json- Contains project information.- Contains dependencies.- Contains npm scripts.Example:"scripts": {    "dev": "vite"}package-lock.json- Records the exact dependency versions installed.- Usually should NOT be manually edited.index.html- Main HTML entry point of the Vite application.- Contains the root element where React is mounted.vite.config.js- Configuration file for Vite.- Used to customize Vite behavior/plugins/settings.eslint.config.js- Configuration file for ESLint.- Defines rules/settings used to check JavaScript/React code.README.md- Documentation/instructions about the project..gitignore- Specifies files/folders that Git should not track.- Example: node_modules/, .env========================================7. ESLINT========================================ESLint = JavaScript/React code analysis tool.Uses:- Finds potential errors.- Detects problematic code.- Finds unused variables.- Enforces coding standards.- Helps maintain consistent code in team projects.eslint.config.js= tells ESLint which rules/settings to use.Interview:"ESLint is a static code-analysis tool used to identifypotential errors and enforce coding standards in JavaScriptand React projects."========================================8. REACT COMPONENTS========================================Component:- A reusable and independent building block of a React UI.- Usually a JavaScript function that returns JSX.Example:const Card = () => {    return (        <div>            <h1>My Card</h1>        </div>    );};========================================9. FUNCTIONAL COMPONENT========================================A functional component is a JavaScript function that returns JSX.Example:const Navbar = () => {    return <nav>This is Navbar</nav>;};========================================10. COMPONENT REUSABILITY========================================The same component can be used multiple times.Example:<Card /><Card /><Card />This avoids writing the same UI code repeatedly.Benefits:- Reusability- Better organization- Easier maintenance- Breaks large UI into smaller parts========================================11. COMPONENT COMPOSITION========================================Large UIs can be created by combining smaller components.Example:App | +-- Navbar +-- Card +-- Card +-- Card +-- FooterExample:const App = () => {    return (        <>            <Navbar />            <Card />            <Card />            <Card />            <Footer />        </>    );};========================================12. COMPONENT NAMING========================================React component names should start with a CAPITAL letter.Correct:<Card /><Navbar /><Footer />Incorrect:<card /><navbar /><footer />Why?JSX uses capitalization to distinguish React componentsfrom built-in HTML elements.Lowercase:<div /><button /><p />-> treated as HTML elements.Capitalized:<Card /><Navbar />-> treated as React components.Interview:"React component names must start with an uppercase letterbecause JSX uses capitalization to distinguish user-definedReact components from built-in HTML elements."========================================13. IMPORT & EXPORT========================================Export:export default Card;Import:import Card from "./Components/Card";Then use:<Card />Flow:Card.jsx   ↓export   ↓App.jsx   ↓import   ↓<Card />========================================14. VARIABLES INSIDE COMPONENTS========================================Example:const Card = () => {    const name = "Ayush";    return (        <h1>My name is {name}</h1>    );};- name is local to the Card component.- It can be used inside Card.- {name} inserts the JavaScript value into JSX.JavaScript uses lexical scoping, so a function can alsoaccess variables from its surrounding scope.========================================15. PROPS========================================Props = Properties.Props are used to pass data from a parent componentto a child component.Props are conceptually similar to function parameters.Example:<Card name="Ayush" age={22} />Here:- name and age are props.- App is the parent component.- Card is the child component.----------------------------------------Receiving Props----------------------------------------The child component can receive props throughthe function parameter.Example:const Card = (props) => {    return (        <h1>{props.name}</h1>    );};Using props:<Card name="Ayush" />Output:Ayush----------------------------------------Passing Multiple Props----------------------------------------Example:<Card    name="Ayush"    age={22}    city="Nagpur"/>Accessing them:{props.name}{props.age}{props.city}----------------------------------------Props with Different Data Types----------------------------------------String:<Card name="Ayush" />Number:<Card age={22} />Boolean:<Card isStudent={true} />Array:<Card skills={["Java", "React", "Node"]} />Object:<Card user={{name: "Ayush", age: 22}} />Important:Strings can be passed directly:name="Ayush"JavaScript values should generally be passedinside curly braces:age={22}isStudent={true}skills={skills}----------------------------------------Props are Read-Only----------------------------------------Props should not be directly modified by thechild component.The parent provides the data and the child uses it.Parent   ↓Props   ↓Child========================================16. REUSABLE COMPONENT USING PROPS========================================Props make reusable components much more powerful.Instead of creating different components for everycard, we can create one Card component and passdifferent data to it.Example:<Card name="Ayush" age={22} city="Nagpur" /><Card name="Ramesh" age={30} city="Mumbai" /><Card name="Amit" age={25} city="Delhi" />The same Card component is reused with different data.Example:const Card = (props) => {    return (        <div>            <h2>{props.name}</h2>            <p>{props.age}</p>            <p>{props.city}</p>        </div>    );};========================================17. ARRAY OF OBJECTS========================================When we have many similar pieces of data,we can store them inside an array of objects.Example:const jobOpenings = [    {        companyName: "Meta",        post: "Frontend Engineer",        pay: "$65/hour"    },    {        companyName: "Amazon",        post: "Backend Developer",        pay: "$70/hour"    },    {        companyName: "Apple",        post: "iOS Developer",        pay: "$90/hour"    }];Each object represents one job.Array  ↓Object  ↓Job data========================================18. map() IN REACT========================================map() is used to go through an array and createsomething for every element.Example:jobOpenings.map(function(elem) {    return <Card />;});Here:elem = current object from the array.If the array contains 3 objects:Object 1 → CardObject 2 → CardObject 3 → CardThis allows us to create multiple componentsfrom data without manually writing:<Card /><Card /><Card />========================================19. PASSING ARRAY DATA AS PROPS========================================We can combine map() and Props.Example:{jobOpenings.map(function(elem) {    return (        <Card            companyName={elem.companyName}            post={elem.post}            pay={elem.pay}        />    );})}Flow:Array of Objects       ↓     map()       ↓     elem       ↓     Props       ↓   Card ComponentThe Card component receives the data:const Card = (props) => {    return (        <div>            <h2>{props.companyName}</h2>            <h3>{props.post}</h3>            <p>{props.pay}</p>        </div>    );};========================================20. KEY PROP========================================When rendering multiple components using map(),React requires each item to have a unique key.Example:{jobOpenings.map(function(elem, idx) {    return (        <Card key={idx} />    );})}key helps React identify which item has changed,been added, or been removed.Example:<Card key={idx} />Important:key is mainly used by React internally.It is NOT automatically available insidethe Card component as:props.keyFor real applications, using a unique ID from thedata is generally better than using the array index.Example:{    id: 1,    companyName: "Meta"}Then:<Card key={elem.id} />========================================21. PROPS DESTRUCTURING========================================Instead of writing:props.companyNameprops.postprops.paywe can destructure props.Example:const Card = ({ companyName, post, pay }) => {    return (        <div>            <h2>{companyName}</h2>            <h3>{post}</h3>            <p>{pay}</p>        </div>    );};This is shorter and commonly used in React.Both approaches are valid:const Card = (props) => {    props.companyName}const Card = ({ companyName }) => {    companyName}========================================IMPORTANT FLOW========================================Parent Component       ↓Array of Objects       ↓map()       ↓Each Object       ↓Props       ↓Reusable Card Component       ↓Different UI for each object========================================22. CSS IN REACT========================================There are multiple ways to add CSS in a React project.The main approaches covered are:1. Global CSS2. Separate CSS Files3. CSS Modules4. Tailwind CSS========================================23. GLOBAL CSS========================================Global CSS means the CSS styles are availablethroughout the application.Example:App.jsximport './App.css';App.css.Card {    background-color: aqua;}Any element/component using:className="Card"can be affected by this CSS.----------------------------------------Advantages----------------------------------------- Simple to understand.- Easy to start with.- Good for global styles.- Useful for basic projects.----------------------------------------Problem: CSS Collision----------------------------------------Global CSS can cause class-name collisions.Example:Card.css.title {    color: red;}Navbar.css.title {    color: blue;}Both classes are still global.If both components use:className="title"their styles can interfere with each other.This is called a CSS collision.========================================24. SEPARATE CSS FILES========================================We can create separate CSS files for differentcomponents to keep the project organized.Example:Components/    Card.jsx    Card.css    Navbar.jsx    Navbar.cssCard.css.Card {    background-color: aqua;}Navbar.css.Navbar {    background-color: aquamarine;}This makes the CSS files easier to organize andmaintain.----------------------------------------Important----------------------------------------Even though the CSS is stored in separate files,normal CSS classes are still GLOBAL.Example:Card.css.title {    color: red;}Navbar.css.title {    color: blue;}The two .title classes can still collide.Separating CSS into different files does NOTautomatically make the styles local.========================================25. CSS SCOPE AND COLLISION========================================Scope means:"Where can this CSS rule affect elements?"Global CSS:    CSS Rule       ↓   Whole ApplicationSeparate CSS Files:    CSS File       ↓   Whole ApplicationThe file is separate, but the class is still global.CSS collision means:Two different components use the same class nameand their CSS rules interfere with each other.Example:.Card {    color: red;}Another CSS file:.Card {    color: blue;}Both use .Card.This can create unexpected styling.========================================26. CSS METHODS COMPARISON========================================| Method              | Scope             | Collision Risk | Organization ||---------------------|-------------------|----------------|--------------|| Global CSS          | Global            | High            | Simple       || Separate CSS Files  | Still Global      | High            | Better       || CSS Modules         | Component-local   | Very Low        | Very Good    || Tailwind CSS        | Utility classes   | Low             | Very Good    |Important:Separate CSS files improve ORGANIZATION,but they do not automatically solve CSS SCOPE.CSS Modules solve the scope/collision problem bymaking class names local to the component.Tailwind CSS uses utility classes instead oftraditional CSS classes for styling.========================================27. CSS MODULES========================================CSS Modules allow CSS to be scoped to a specificcomponent.Instead of creating:Card.csswe create:Card.module.cssExample:Card.module.css.Card {    background-color: aqua;}The CSS is locally scoped to the component usingthat module.----------------------------------------Why CSS Modules?----------------------------------------CSS Modules help prevent class-name collisions.For example:Card.module.css.Card {    background-color: aqua;}Navbar.module.css.Navbar {    background-color: aquamarine;}Even if different components use similar class names,their styles are scoped to their respective modules.----------------------------------------Basic Idea----------------------------------------Normal CSS:class name     ↓  GlobalCSS Module:class name     ↓Component-localThis makes component styling safer and easier tomaintain in larger React applications.========================================28. TAILWIND CSS========================================Tailwind CSS is a utility-first CSS framework.Instead of writing custom CSS rules for every element,we use predefined utility classes directly in JSX.Example:<button className="bg-black text-white px-4 py-2 rounded">    Apply Now</button>Here:bg-black   → background colortext-white → text colorpx-4       → horizontal paddingpy-2       → vertical paddingrounded    → rounded corners----------------------------------------Why Tailwind CSS?----------------------------------------- Faster UI development.- Styles can be written directly in JSX.- Provides many ready-to-use utility classes.- Reduces the need to create separate CSS files.- Easy to build consistent designs.----------------------------------------Tailwind vs Normal CSS----------------------------------------Normal CSS:.button {    background-color: black;    color: white;    padding: 8px 16px;    border-radius: 8px;}Then:<button className="button">    Apply Now</button>Tailwind:<button className="bg-black text-white px-4 py-2 rounded">    Apply Now</button>The styling is written directly using utilityclasses.========================================29. CSS APPROACHES COMPARISON========================================| Method              | Scope             | Collision Risk | Main Idea ||---------------------|-------------------|----------------|-----------|| Global CSS          | Global            | High            | CSS available throughout the app || Separate CSS Files  | Still Global      | High            | Organize CSS into different files || CSS Modules         | Component-local   | Very Low       | CSS scoped to a component || Tailwind CSS        | Utility classes   | Low             | Style using utility classes |Important:Separate CSS files improve organization butdo NOT automatically make CSS local.CSS Modules solve the CSS scope/collision problem.Tailwind uses utility classes instead of writingtraditional CSS for every component.========================================30. CSS LEARNING FLOW========================================Global CSS     ↓Separate CSS Files     ↓CSS Modules     ↓Tailwind CSSEach approach provides a different way to organizeand apply styles in a React application.========================================31. TAILWIND CSS — UTILITY-FIRST APPROACH========================================Tailwind CSS is a utility-first CSS framework.Instead of writing separate CSS rules like:.card {    background-color: black;    color: white;    padding: 16px;}We use utility classes directly in JSX:<div className="bg-black text-white p-4">```Common examples:```bg-black        → background colortext-white      → text colorp-4             → paddingpx-4            → horizontal paddingpy-2            → vertical paddingmt-4            → margin-toprounded         → border radiusflex            → display flex```Main idea:Traditional CSS↓Write CSS separately↓Apply classTailwind CSS↓Use utility classes directly↓Style the element========================================32. TAILWIND RESPONSIVE DESIGN==============================Tailwind provides responsive prefixes.Common breakpoints:```sm:   → small screensmd:   → medium screenslg:   → large screensxl:   → extra large screens2xl:  → very large screens```Example:```text-xl md:text-2xl lg:text-4xl```Meaning:```Default → text-xlMedium screen → text-2xlLarge screen → text-4xl```Important:Tailwind follows a mobile-first approach.Classes without a prefix apply to all screen sizes,and prefixed classes apply from that breakpoint upward.========================================33. FLEXBOX IN TAILWIND=======================Tailwind uses utility classes to control Flexbox.```flex    ↓Creates a flex container```Common Flexbox utilities:```flexflex-rowflex-coljustify-centerjustify-betweenjustify-arounditems-centeritems-startitems-endgap-4flex-wrap```Example:```<div className="flex justify-between items-center">flex    → enables Flexboxjustify-between    → distributes items along the main axisitems-center    → aligns items along the cross axis```Important:`flex-col` does NOT create a flex container.It only changes the direction of analready existing flex container.========================================34. WIDTH AND HEIGHT IN TAILWIND================================Tailwind provides utility classes for width and height.Examples:```w-fullw-1/2w-[30%]w-[325px]h-fullh-screenh-[75vh]```Arbitrary values can be written using:```[value]```Example:```w-[325px]h-[75vh]ml-[30px]```This is useful when the default Tailwind spacingvalues do not match the required design.========================================35. POSITIONING IN TAILWIND===========================Tailwind provides positioning utilities.```staticrelativeabsolutefixedsticky```Important relationship:```Parent   ↓relative   ↓Child   ↓absolute```Example:```<div className="relative">    <h3 className="absolute top-6 left-6">        1    </h3></div>```The `absolute` element is positioned relative tothe nearest parent with a positioning context,commonly a `relative` parent.Common positioning utilities:```top-0top-6bottom-5left-6right-4```========================================36. OBJECT-FIT FOR IMAGES=========================When an image needs to fit inside a fixed-size area,Tailwind provides object-fit utilities.Common classes:```object-coverobject-contain```object-cover:```Image fills the container↓Some part of the image may be cropped```object-contain:```Entire image remains visible↓Empty space may appear around the image```For card images where the image should completelyfill the card:```object-cover```Example:```<img className="w-full h-full object-cover" />```========================================37. SHRINK-0 IN FLEXBOX=======================`shrink-0` prevents a flex item from becomingsmaller when there is not enough space.Example:```<div className="w-[325px] shrink-0">```Without `shrink-0`:```Flexbox   ↓May shrink the card   ↓Card becomes smaller than expected```With `shrink-0`:```Fixed width   ↓Card keeps its width```This is especially useful when creatinghorizontal scrolling card layouts.========================================38. HORIZONTAL SCROLLING========================Tailwind provides overflow utilities.```overflow-x-auto    → Allows horizontal scrolling when neededoverflow-x-scroll    → Always shows/creates horizontal scrolling```Example:```<div className="flex overflow-x-auto">    <Card />    <Card />    <Card /></div>```For cards:```flex   ↓Cards placed horizontally   ↓Content becomes wider than container   ↓overflow-x-auto   ↓Horizontal scrolling```Important:If the entire page starts scrolling horizontallyinstead of only the cards, check the width of theparent flex items.========================================39. PROPS DRILLING==================Props drilling means passing data through multiplecomponents to reach the component that needs it.Example:```App ↓Page1 ↓MainContent ↓RightSection ↓Card```If `cards` is created in App:```App ↓cards ↓Page1 ↓cards ↓MainContent ↓cards ↓RightSection ↓map() ↓Card```The data is passed down through the component tree.This is called:PROPS DRILLING========================================40. CALLING FUNCTIONS IN REACT========================================In React, functions can be executed whenan event occurs.Example events:onClickonDoubleClickonChangeonMouseEnteronMouseMoveonWheelBasic flow:User performs an event        ↓React detects the event        ↓Function runs        ↓Code inside the function executes========================================41. onClick EVENT========================================`onClick` runs a function when an elementis clicked.Example:<button onClick={btnClicked}>    Click</button>Important:Do NOT call the function while passing it.Correct:onClick={btnClicked}Incorrect:onClick={btnClicked()}Why?`onClick={btnClicked}`→ Gives React the function→ React calls it when the button is clicked.onClick={btnClicked()}→ Calls the function immediately→ It does not wait for the click.========================================42. DIFFERENT WAYS TO RUN A FUNCTION========================================There are multiple ways to handle an event.1. Pass an existing function:onClick={btnClicked}2. Create a function directly:onClick={() => {    console.log("Button clicked");}}3. Call another function inside a function:onClick={() => {    btnClicked();}}The important difference is:Function reference        ↓Wait for the eventFunction call ()        ↓Runs immediately========================================43. COMMON REACT EVENTS========================================React provides event handlers for differentuser interactions.onClick→ Runs when an element is clicked.onDoubleClick→ Runs when an element is double-clicked.onMouseEnter→ Runs when the mouse enters an element.onMouseMove→ Runs when the mouse moves over an element.onChange→ Runs when the value of an input changes.onWheel→ Runs when the mouse wheel is used.Example concept:<button onClick={btnClicked}>    Click</button><div onMouseEnter={mouseEntered}>    Box</div><input onChange={inputChanged} />========================================44. Hooks are special functions provided by React that allow functional components to use React features such as:* **State** — Stores data that can change and automatically update the UI when changed.* **Context** — Allows components to share data without passing props through every level.* **Effects** — Handles side effects such as API calls, timers, or interacting with external systems.* **References** — Lets us directly keep a reference to a DOM element or a mutable value without causing a re-render.* **Performance optimization** — Helps avoid unnecessary calculations or function recreations using Hooks like `useMemo` and `useCallback`.Before Hooks, functional components had limitations when we wanted to manage things like **state**.Hooks made it possible to use these React features inside functional components.---# 57. Why Do We Need Hooks?Suppose we create a normal variable:```jsxlet count = 0;```and later change it:```jsxcount = count + 1;```The JavaScript variable changes, but **React does not automatically re-render the UI**.So:```textNormal Variable      ↓Value changes      ↓❌ React doesn't know it should update UI```Hooks solve this problem.```textState  ↓State changes  ↓React knows about the change  ↓Component re-renders  ↓UI updates```---# 58. useState HookThe first Hook we learn is:```jsxuseState```It is used to create and manage **state** inside a functional component.Basic structure:```jsxconst [value, setValue] = useState(initialValue);```Example:```jsxconst [count, setCount] = useState(0);```Here:```textcount   ↓Current state valuesetCount   ↓Function used to change state0   ↓Initial value```---# 59. State and State SetterWhen we write:```jsxconst [count, setCount] = useState(0);```React gives us two things:```textcount   ↓Current valuesetCount()   ↓Function to update the value```We should **not directly change** the state variable.❌ Don't do:```jsxcount = 10;```Instead:```jsxsetCount(10);```The setter function is provided by React through `useState`.---# 60. State Update → Re-renderWhen we call:```jsxsetCount(10);```React updates the state and re-renders the component.Flow:```textsetCount(10)      ↓State changes      ↓React re-renders component      ↓Updated value appears in UI```This is why your counter from the previous exercise worked:```textClick +   ↓counter()   ↓setCount(count + 1)   ↓React re-renders   ↓0 → 1```🔥 This is the exact thing we couldn't properly do before learning Hooks.---# 61. State Is Different From Normal Variables### Normal variable```jsxlet count = 0;```Changing it:```jsxcount++;```doesn't tell React to update the UI.### State```jsxconst [count, setCount] = useState(0);```Changing it:```jsxsetCount(count + 1);```tells React that the state has changed.```textNormal Variable      ↓JavaScript onlyState      ↓React-managed value      ↓UI can update```---# 62. Multiple StatesA component can have multiple state variables.Example:```jsxconst [count, setCount] = useState(0);const [name, setName] = useState("");```Each state has its own setter.```textcount → setCount()name → setName()```You already did this in your practice:```jsxconst [count, setcount] = useState(0);const [lastclicked, setlastclicked] =    useState('not clicked yet');```So you have already practiced **multiple states**. 😎---# 63. Hooks Must Be Used Inside ComponentsHooks such as:```jsxuseState()```are used inside React functional components.Example:```jsxconst App = () => {    const [count, setCount] = useState(0);    return (        <h1>{count}</h1>    );}```Think:```textComponent   ↓Hook   ↓React feature```---# 64. Hooks Are Not Just useStateReact has several Hooks.Some important ones:```textuseState   ↓State managementuseEffect   ↓Side effectsuseContext   ↓ContextuseRef   ↓References / mutable valuesuseMemo   ↓OptimizationuseCallback   ↓Optimization```**Don't try to memorize all of them now.**The instructor's approach is to understand Hooks **one by one**, starting with `useState`, then moving to other Hooks gradually.---# 🧠 Important Flow```textNormal Variable      ↓Doesn't trigger React re-render``````textuseState      ↓State      ↓Setter function      ↓State changes      ↓React re-renders      ↓UI updates```---# 65. Two-Way Data BindingTwo-way binding is a way to manage input values using React state.The input's value is connected to state, and whenever the user changes the input, the state is updated.```textInput  ↓onChange  ↓setState()  ↓State changes  ↓Input updates```---# 67. `onChange` and `e.target.value``onChange` runs whenever the value of an input changes.The current value entered by the user can be accessed using:```jsxe.target.value```So:```textUser types    ↓onChange    ↓e.target.value    ↓Get current input value```---# 68. `value` and StateWe can connect an input's `value` to a state variable.For example, if the input's value is connected to `title`, React controls what value is displayed inside the input.If the state changes, the input value also changes.This is the main connection used in **two-way binding**.---# 69. useful when we want to store some information **without using a backend/database**.Example:* Website theme (Dark/Light mode)* Login-related information* Small pieces of website active**.* When the browser is closed, the stored data is removed.### LocalStorage* Data remains stored for that website/URL.* It remains even after:  * Reloading the website  * Closing the website  * Closing the browser  * Restarting the system### Easy Difference| Storage          | Data remains until               || ---------------- | -------------------------------- || `sessionStorage` | Browser session ends             || `localStorage`   | Data is manually removed/cleared |---## #82 Clearing StorageBoth LocalStorage and SessionStorage provide a `clear()` method.### LocalStorage`localStorage.clear()`→ Clears all data from LocalStorage.### SessionStorage`sessionStorage.clear()`→ Clears all data from SessionStorage.---## #83 setItem() — Store DataTo store data in LocalStorage:`localStorage.setItem(key, value)`LocalStorage stores data in **key-value pairs**.Example concept:```textkey       → value"user"    → "Sarthak"```So:* `user` = key* `Sarthak` = value`setItem()` is used to **set/store an item** in LocalStorage.---## #84 getItem() — Retrieve DataTo retrieve stored data:`localStorage.getItem(key)``getItem()` requires the **key**.Example concept:```textlocalStorage"user" → "Sarthak"getItem("user")        ↓"Sarthak"```So:* `setItem()` → Store* `getItem()` → Retrieve---## #85 removeItem() — Remove DataTo remove a particular item:`localStorage.removeItem(key)`It removes the data associated with the given **key**.Example:```text"user" → "Sarthak"removeItem("user")"user" → removed```---## #86 Four Important LocalStorage MethodsThe instructor highlights **4 important methods**:| Method         | Purpose                     || -------------- | --------------------------- || `setItem()`    | Set/store an item           || `getItem()`    | Get/retrieve an item        ||
