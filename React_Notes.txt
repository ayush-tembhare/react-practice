react boilerplate : rafceWhat is react js?> React js is a javascript library which is used to make ui (frontend).It is was made by meta(facebook) in 2013Story of react js (why and how it was made):-Why React Was Made (The Problem at Facebook):Around 2010–2011, Facebook was growing rapidly and facing significant UI/UX challenges built on standard HTML, CSS, and traditional JavaScript:Whole-Page Reloads for Minor Updates: In early Facebook's UI, if you received a message, friend request, or notification while scrolling, the UI counter (e.g., message count 3) wouldn't update dynamically. To see the updated count, the entire web page had to be reloaded/re-rendered.Poor User Experience: Constantly reloading static HTML pages for small data changes created a sluggish and clunky experience for millions of daily active users.How React Solved It (The Solution & Birth of React):To tackle this DOM updating issue, Jordan Walke (a software engineer at Facebook) created React to overhaul how dynamic user interfaces are built:Component-Based Architecture : Instead of treating a web page as a single massive HTML document, React breaks the UI down into independent, reusable chunks (components). If a notification count changes, only that specific notification component re-renders while the rest of the page remains untouched.Virtual DOM : React introduced a Virtual DOM (an in-memory lightweight copy of the real DOM). Whenever state changes occur, React compares the Virtual DOM with the Real DOM and updates only the specific elements that actually changed, making applications buttery smooth and fast without full-page reloads.Official Release : Facebook initially deployed React on News Feed (2011) and later Instagram (2012), before open-sourcing it to the public in 2013.different types of js library(library are used to add features in a website):  - React----------------------------------------- React is a JavaScript library for building user interfaces (UI).- It is mainly focused on the UI/view layer.- React is flexible, so we can choose additional tools/libraries  according to our project needs.React vs Angular/Vue:- React -> Library, more flexible- Angular -> Framework, more opinionated/full solution- Vue -> Framework, provides more built-in structure/features========================================2. JSX========================================JSX = JavaScript XML- JSX allows us to write HTML-like syntax inside JavaScript.- It makes React UI code easier to write and understand.- JSX is NOT exactly HTML; it is syntax that gets transformed  into JavaScript.Example:const name = "Ayush";const App = () => {    return <h1>Hello {name}</h1>;};========================================3. JSX RULES========================================1. Only one parent element can be returned.Correct:<div>    <h1>Hello</h1>    <p>Welcome</p></div>OR use Fragment:<>    <h1>Hello</h1>    <p>Welcome</p></>2. Use className instead of class.HTML:<div class="card">JSX:<div className="card">3. All tags must be properly closed.Correct:<img /><input /><br />4. JavaScript expressions are written inside { }.Example:const name = "Ayush";<h1>Hello {name}</h1>5. Inline CSS uses a JavaScript object and camelCase properties.Example:<h1 style={{ fontSize: "30px", backgroundColor: "red" }}>    Hello</h1>CSS:font-sizebackground-colorJSX:fontSizebackgroundColor========================================4. JSX EXPRESSIONS========================================Curly braces { } allow JavaScript expressions inside JSX.Example:const name = "Ayush";const age = 22;return (    <div>        <h1>{name}</h1>        <p>{age}</p>        <p>{2 + 2}</p>    </div>);Output:Ayush224========================================5. VITE========================================Vite is a modern frontend development/build tool.It is commonly used to create and run React projects.Creating a React project:npm create vite@latestThen:npm installRun development server:npm run devVite provides:- Fast development server- Fast updates during development- Production build========================================6. IMPORTANT VITE FILES========================================package.json- Contains project information.- Contains dependencies.- Contains npm scripts.Example:"scripts": {    "dev": "vite"}package-lock.json- Records the exact dependency versions installed.- Usually should NOT be manually edited.index.html- Main HTML entry point of the Vite application.- Contains the root element where React is mounted.vite.config.js- Configuration file for Vite.- Used to customize Vite behavior/plugins/settings.eslint.config.js- Configuration file for ESLint.- Defines rules/settings used to check JavaScript/React code.README.md- Documentation/instructions about the project..gitignore- Specifies files/folders that Git should not track.- Example: node_modules/, .env========================================7. ESLINT========================================ESLint = JavaScript/React code analysis tool.Uses:- Finds potential errors.- Detects problematic code.- Finds unused variables.- Enforces coding standards.- Helps maintain consistent code in team projects.eslint.config.js= tells ESLint which rules/settings to use.Interview:"ESLint is a static code-analysis tool used to identifypotential errors and enforce coding standards in JavaScriptand React projects."========================================8. REACT COMPONENTS========================================Component:- A reusable and independent building block of a React UI.- Usually a JavaScript function that returns JSX.Example:const Card = () => {    return (        <div>            <h1>My Card</h1>        </div>    );};========================================9. FUNCTIONAL COMPONENT========================================A functional component is a JavaScript function that returns JSX.Example:const Navbar = () => {    return <nav>This is Navbar</nav>;};========================================10. COMPONENT REUSABILITY========================================The same component can be used multiple times.Example:<Card /><Card /><Card />This avoids writing the same UI code repeatedly.Benefits:- Reusability- Better organization- Easier maintenance- Breaks large UI into smaller parts========================================11. COMPONENT COMPOSITION========================================Large UIs can be created by combining smaller components.Example:App | +-- Navbar +-- Card +-- Card +-- Card +-- FooterExample:const App = () => {    return (        <>            <Navbar />            <Card />            <Card />            <Card />            <Footer />        </>    );};========================================12. COMPONENT NAMING========================================React component names should start with a CAPITAL letter.Correct:<Card /><Navbar /><Footer />Incorrect:<card /><navbar /><footer />Why?JSX uses capitalization to distinguish React componentsfrom built-in HTML elements.Lowercase:<div /><button /><p />-> treated as HTML elements.Capitalized:<Card /><Navbar />-> treated as React components.Interview:"React component names must start with an uppercase letterbecause JSX uses capitalization to distinguish user-definedReact components from built-in HTML elements."========================================13. IMPORT & EXPORT========================================Export:export default Card;Import:import Card from "./Components/Card";Then use:<Card />Flow:Card.jsx   ↓export   ↓App.jsx   ↓import   ↓<Card />========================================14. VARIABLES INSIDE COMPONENTS========================================Example:const Card = () => {    const name = "Ayush";    return (        <h1>My name is {name}</h1>    );};- name is local to the Card component.- It can be used inside Card.- {name} inserts the JavaScript value into JSX.JavaScript uses lexical scoping, so a function can alsoaccess variables from its surrounding scope.========================================15. PROPS========================================Props = Properties.Props are used to pass data from a parent componentto a child component.Props are conceptually similar to function parameters.Example:<Card name="Ayush" age={22} />Here:- name and age are props.- App is the parent component.- Card is the child component.----------------------------------------Receiving Props----------------------------------------The child component can receive props throughthe function parameter.Example:const Card = (props) => {    return (        <h1>{props.name}</h1>    );};Using props:<Card name="Ayush" />Output:Ayush----------------------------------------Passing Multiple Props----------------------------------------Example:<Card    name="Ayush"    age={22}    city="Nagpur"/>Accessing them:{props.name}{props.age}{props.city}----------------------------------------Props with Different Data Types----------------------------------------String:<Card name="Ayush" />Number:<Card age={22} />Boolean:<Card isStudent={true} />Array:<Card skills={["Java", "React", "Node"]} />Object:<Card user={{name: "Ayush", age: 22}} />Important:Strings can be passed directly:name="Ayush"JavaScript values should generally be passedinside curly braces:age={22}isStudent={true}skills={skills}----------------------------------------Props are Read-Only----------------------------------------Props should not be directly modified by thechild component.The parent provides the data and the child uses it.Parent   ↓Props   ↓Child========================================16. REUSABLE COMPONENT USING PROPS========================================Props make reusable components much more powerful.Instead of creating different components for everycard, we can create one Card component and passdifferent data to it.Example:<Card name="Ayush" age={22} city="Nagpur" /><Card name="Ramesh" age={30} city="Mumbai" /><Card name="Amit" age={25} city="Delhi" />The same Card component is reused with different data.Example:const Card = (props) => {    return (        <div>            <h2>{props.name}</h2>            <p>{props.age}</p>            <p>{props.city}</p>        </div>    );};========================================17. ARRAY OF OBJECTS========================================When we have many similar pieces of data,we can store them inside an array of objects.Example:const jobOpenings = [    {        companyName: "Meta",        post: "Frontend Engineer",        pay: "$65/hour"    },    {        companyName: "Amazon",        post: "Backend Developer",        pay: "$70/hour"    },    {        companyName: "Apple",        post: "iOS Developer",        pay: "$90/hour"    }];Each object represents one job.Array  ↓Object  ↓Job data========================================18. map() IN REACT========================================map() is used to go through an array and createsomething for every element.Example:jobOpenings.map(function(elem) {    return <Card />;});Here:elem = current object from the array.If the array contains 3 objects:Object 1 → CardObject 2 → CardObject 3 → CardThis allows us to create multiple componentsfrom data without manually writing:<Card /><Card /><Card />========================================19. PASSING ARRAY DATA AS PROPS========================================We can combine map() and Props.Example:{jobOpenings.map(function(elem) {    return (        <Card            companyName={elem.companyName}            post={elem.post}            pay={elem.pay}        />    );})}Flow:Array of Objects       ↓     map()       ↓     elem       ↓     Props       ↓   Card ComponentThe Card component receives the data:const Card = (props) => {    return (        <div>            <h2>{props.companyName}</h2>            <h3>{props.post}</h3>            <p>{props.pay}</p>        </div>    );};========================================20. KEY PROP========================================When rendering multiple components using map(),React requires each item to have a unique key.Example:{jobOpenings.map(function(elem, idx) {    return (        <Card key={idx} />    );})}key helps React identify which item has changed,been added, or been removed.Example:<Card key={idx} />Important:key is mainly used by React internally.It is NOT automatically available insidethe Card component as:props.keyFor real applications, using a unique ID from thedata is generally better than using the array index.Example:{    id: 1,    companyName: "Meta"}Then:<Card key={elem.id} />========================================21. PROPS DESTRUCTURING========================================Instead of writing:props.companyNameprops.postprops.paywe can destructure props.Example:const Card = ({ companyName, post, pay }) => {    return (        <div>            <h2>{companyName}</h2>            <h3>{post}</h3>            <p>{pay}</p>        </div>    );};This is shorter and commonly used in React.Both approaches are valid:const Card = (props) => {    props.companyName}const Card = ({ companyName }) => {    companyName}========================================IMPORTANT FLOW========================================Parent Component       ↓Array of Objects       ↓map()       ↓Each Object       ↓Props       ↓Reusable Card Component       ↓Different UI for each object
